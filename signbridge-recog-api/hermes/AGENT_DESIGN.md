# 결선 서비스 설계 메모 — 수어 영상 → 청인용 메시지 (Hermes Agent + SignBridge API)

> 아이디어·설계 정리용. 에이전트 지침 문장 자체는 대회 플랫폼 안에서 쓴다.

## 1. 문제 정의 (심사 30점)

- 농인이 병원 접수·약국·관공서·직장에서 청인에게 **급히 말을 전해야 할 때** 통역사가 옆에 없다.
- 필담은 느리고, 한국수어 어순(예: "머리 어제 아프다")을 그대로 적으면 청인에게 어색하게 읽힌다.
- 예선 스킬("하기 어려운 말 대신 써드려요")은 **글로 상황을 설명할 수 있는 사람**용이었다. 결선은 입력을 **수어 영상**으로
  바꿔, 같은 "상황·상대에 맞는 메시지 작성" 능력을 농인에게 연다.
- 빈도·시간(사용자가 실제 수치로 채울 것): 통역 공백이 생기는 일상 상황 수/주, 필담으로 걸리는 시간 vs 목표 30초.

## 2. 흐름

```
① 수어 영상 업로드(3~8초, 정면, 손·상반신 보이게)
② recognizeSignVideo 호출  ──▶ status · glosses · words[].alts · sentence · mirrored
③ status ≠ ok ─▶ 재촬영 안내(손/상반신 안 보임)                      ─┐
④ 낮은 confidence 낱말 ─▶ 후보(alts) 번호로 보여 주고 사용자가 고름   ─┤ 사람이 확정
⑤ 확정 글로스 열 + 누구에게/어디서 ─▶ Solar Pro 4가 청인용 문장 작성  ─┘
⑥ 출력 2종: 현장용 짧은 말 / 문자용 정중한 말 (+ 상대 답변을 받아 다시 농인에게 요약)
```

- LLM(Solar Pro 4)의 역할은 **⑤ 문장 작성**뿐이다. 낱말 인식은 API가 하고, 확정은 사람이 한다.
- `sentence`(규칙 기반 폴백)는 "API만으로도 뜻이 통하는 최소 문장"이다. LLM이 실패해도 이것을 보여 준다.

## 3. 도구 사용 규칙(지침에 반영할 요점)

| 상황 | 규칙 |
|---|---|
| 호출 | 영상은 `POST /recognize/video` multipart `file`. 기본값 그대로(`mode=segmental`, `mirror=auto`) |
| `status` ≠ `ok` | 인식 결과 없음. 지어내지 말고 재촬영 안내: "손과 상반신이 보이게, 정면에서, 3~8초" |
| `confidence` < 0.5 | 그 낱말의 `alts`를 번호로 제시하고 고르게 한다. 고르기 전엔 문장을 만들지 않는다 |
| 문장 작성 | `glosses`(또는 사용자가 고친 열)에 **있는 낱말만** 쓴다. 없는 정보(날짜·이름·금액)는 빈칸 |
| `mirrored: true` | "거울상 영상으로 판단해 반전해 읽었다"고 한 줄 알린다. 결과가 이상하면 `mirror=off`로 한 번 더 |
| API 무응답·타임아웃 | 사용자에게 알리고 **텍스트 입력 경로(예선 스킬 흐름)** 로 넘어간다 |
| 낱말이 문장이 안 될 때 | "'병원 가다 약' 맞나요?"처럼 있는 낱말로 되묻는다 |

## 4. 예외·실패 처리 표 (심사 "설계 체계성" 30점)

| 입력 | 처리 |
|---|---|
| 영상 없음 / 영상 아닌 파일 | 형식 안내(mp4·webm·mov), 텍스트로도 가능하다고 안내 |
| 30초 넘는 영상 | 앞 30초만 본다고 알림(`max_seconds`) |
| 손이 안 보임(`no_hands`) | 재촬영 안내, 원인 문장(손이 화면 밖/너무 어두움) |
| 상반신 없음(`no_pose`) | 재촬영 안내(카메라를 멀리) |
| 낱말 0개(status ok, words 빈 배열) | "동작을 한 낱말씩 잠깐 멈추며 해 주세요" + `mode=stream` 재시도 |
| 후보 중에 맞는 게 없음 | 낱말을 글자로 입력받아 대체 |
| 상대/장소 미상 | 되묻되, 초안(중립 존댓말)을 먼저 보여 준다 |

## 5. 심사 기준 대응

- **재현 가능성(20)**: 공개 API + OpenAPI 스펙. 심사위원은 영상 1개만 올리면 된다. 절전 방지 핑, 제출 전 새 대화창 3회 리허설.
- **독창성(20)**: 참가자 본인이 학습한 13,576 클래스 수어 인식 모델을 **비-LLM 외부 API**로 붙였고, LLM은 문장 작성만 맡는
  역할 분리. 확신 낮은 낱말을 **후보로 되묻는 UX**로 오역 전달을 막는다.
- **문제 정의(30)**: 통역 공백 + 수어-한국어 문법 차이라는 구체 상황. 실제 수치를 넣을 것.
- **설계 체계성(30)**: 위 4절 표를 지침에 그대로 반영.

## 6. 발표(9/19) 데모

| 시나리오 | 수어(글로스) | 기대 출력 |
|---|---|---|
| A 병원 접수 | 머리 · 어제 · 아프다 | "어제부터 머리가 아파요. 접수 부탁드립니다." |
| B 직장 조퇴 | 오늘 · 몸 · 아프다 · 집 · 가다 | 상사에게 보내는 정중한 조퇴 요청 문자 |
| C 약국 | 약 · 어디 · 있다 | "약은 어디에 있나요?" |

- 사전 녹화 영상 3개 준비(현장 네트워크·조명 실패 대비), 라이브는 1개만.
- 데모 낱말은 `GET /labels?q=`로 **모델에 있는 글로스인지 먼저 확인**하고, 낱말 사이를 잠깐 멈춰서 찍는다.
- 실측 성능(연속 수어 F1 0.65, 낱말 단위 top-1 0.80)을 슬라이드에 **그대로** 적는다 — 과장하지 않는 편이 심사에 유리하다.

## 7. 리스크

| 리스크 | 대비 |
|---|---|
| 심사 시점 API 다운(=실격) | HF Space `/health` 20분 간격 핑, 제출 직전·발표 직전 확인, 텍스트 폴백 경로 |
| 인식률(연속 수어) | 데모 문장은 잘 잡히는 낱말로, 한 낱말씩 멈추며 촬영, `alts` 확인 단계 |
| 전면 카메라 거울상 | `mirror=auto` (17/17 판정), 응답 `mirrored`로 알림 |
| Hermes가 파일을 API로 못 넘김 | OT에서 확인. 안 되면 사용자가 영상을 웹앱(signbridge)에서 돌려 **랜드마크 JSON** 또는 결과 텍스트를 붙이는 경로 |
| ctc-v1(연속 인식) 미확보 | 현 단어 모델 + 투표 디코더로 진행. 가중치 찾으면 `mode=ctc` 추가 |
